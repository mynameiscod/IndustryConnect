# Database schema and invariants

All collections use Mongoose timestamps. References are ObjectIds; public JSON uses strings. Monetary values are safe integers in paise, currency INR. Store instants in UTC and IANA timezone names for display. Indexes are explicit; deploy with `npm run db:indexes` before serving traffic. Production does not auto-build indexes.

## Validation and retention

API validation rejects unknown request properties, invalid references and malformed amounts before database operations. Mongoose schema validation is defense in depth. Financial/audit records are never TTL-deleted. Session/challenge expiration is enforced at request time. Define business/legal retention periods and account-deletion/anonymization procedures before public launch; no invented statutory retention promise.

## Integrity cases

1. A public listing references an approved active expert and active category/service.
2. A slot is held/booked by at most one booking; booking and slot change atomically.
3. Booking price/commission/policy are snapshots unaffected by later settings edits.
4. Every capture has one immutable ledger posting; duplicate/out-of-order events cannot downgrade captured payment.
5. A released slot never reacquires its earlier booking after late payment.
6. One paid completed booking permits exactly one customer review and one payout record.
7. Sensitive user, provider and meeting fields are not included in public queries.

Mongo is isolated under database `expert_marketplace`. Local development replicas may use ephemeral test DBs; production secrets and data are never copied into fixtures.
